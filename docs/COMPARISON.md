# 与飞书官方「下载为 Word」的对比

> 生成方式：`tools/fetch-official-word3.mjs` 自动走飞书 UI 下载官方产物，
> `tools/compare-official.mjs` 做 XML 数值对比，`docx2pdf.ps1` + PyMuPDF 做页数与像素级比对。
> 基准产物存放于 `samples/official/`。

## 一、六篇文档总览（2026-10-17）

| 文档 | 块数 | 我们页数 | 官方页数 | 段落数（我们/官方） | 顶层表格 | 降级项 |
| --- | --- | --- | --- | --- | --- | --- |
| IIoT 试验任务接口开发文档 | 845 | **26** | 26 | 629 / 510 | 24 / 25* | 2 项（附件链接、多维表格） |
| 成都圣恩 MES 接口功能文档 | 370 | 14 | **13** | 326 / 223 | 19 / 19 | 0 |
| 长期项目方案与执行 | 81 | **4** | 4 | 60 / 62 | 一致 | 1 项（多维表格） |
| 产品功能 Checklist（超宽表格） | 7 | **1** | 1 | — | 一致 | 0 |
| 竞品功能调研 | 300 | 5 | **6** | 177 / 167 | 14 / 14 | 1 项（多维表格） |
| 部门季报/半年报/年报 | 61 | 3 | **4** | 49 / 48 | 一致 | 6 项（飞书专有块） |

\* IIoT 那篇官方多 1 个表格，是它把引用块也做成单格表格且统计口径含嵌套表；逐表核对后两边内容一致。

**结论**：6 篇里 3 篇页数完全一致，另外 3 篇相差 1 页——差异来自字体/字号选择（我们微软雅黑 12pt，官方等线 11pt），属既定设计而非缺陷。

## 二、已按官方对齐的部分

| 项 | 官方值 | 我们 |
| --- | --- | --- |
| 引用块结构 | 单格表格 + 左边框 | 同 |
| 引用竖线 | `BBBFC4` / `sz=18` | 同 |
| 引用正文色 | `646A73`（灰） | 同 |
| 引用单元格内边距 | 上60/左120/下30/右120 | 同 |
| 引用段落间距 | 前120/后120，`line=288`（1.2倍） | 同 |
| 表格框线 | `DEE0E3` | 同 |
| 表头底纹 | `EFF0F1` | 同 |

像素级验证（300dpi 采样，IIoT 文档第 15 页引用区）：
正文主色 `#636A73` = 官方 `#636A73`；竖线 `#BABEC4` = 官方 `#BABEC4`，竖线像素数 588 = 588。

## 三、有意保留的差异

| 项 | 官方 | 我们 | 为什么保留 |
| --- | --- | --- | --- |
| 段落样式 | **完全没有样式**，全部直接格式 | Fde* 样式体系 + Word 内置样式映射 | 我们的产物可以「改一次样式全文生效」；官方产物要改标题得逐个选 |
| 正文字体/字号 | 等线 / Arial 11pt | 微软雅黑 12pt | 用户既定要求 |
| 页边距 | 默认 1440（1 英寸） | 900（0.62 英寸） | 用户既定要求，版心更接近在线 |
| 图片宽度 | 5257800 EMU（552px） | 6419850 EMU（674px） | 我们铺满版心，视觉更饱满 |
| 代码块 | 整块塞进一个单元格（内部换行） | 每行一个段落 | 便于逐行编辑与对比 |
| 页眉页脚 | 有空引用但内容为空 | 不生成 | 等价 |

## 四、复现命令

```bash
# 1) 下载官方产物（需调试 Chrome 已登录并打开目标文档）
node tools/fetch-official-word3.mjs

# 2) 导出我们的产物
node tools/export-run.mjs r050 <文档URL>

# 3) 数值对比
node tools/compare-official.mjs "samples/official/<官方>.docx" "samples/runs/r050/source.docx"

# 4) 页数/像素对比
powershell -File tools/docx2pdf.ps1 -Src <docx> -Dst <pdf>
```
