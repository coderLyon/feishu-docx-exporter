## r034–r035（2026-10-17）：修复「导出的 docx 打不开」（严重）

**现象**：用户反馈项目模板（doc2）导出的 Word **完全无法打开**。
**根因**：该文档正文里有一个 `0x08` 控制字符（退格符），被原样写进 `word/document.xml`。
XML 1.0 禁止 0x20 以下的控制字符，Word 于是判定文件损坏——报的是「无法打开」，不会提示非法字符，
排查时容易误以为是样式或关系文件的问题。

**排查方法**（可复用）：逐个 XML 部件用 XML 解析器验证 + 扫描非法码位，一次定位到 `document.xml` 第 9398 字节。
27 份历史产物扫描后仅这一份中招。

**修复**：
1. 新增 `sanitizeXmlText()`：剔除非法控制字符与保留码位（U+FFFE/U+FFFF），并把**落单代理项**替换为 U+FFFD（合法 emoji 是成对代理项，必须保留）
2. 接入三处：`text.js` 的富文本解析出口（段落/标题/表格/代码块/题注的咽喉）、`runs.js` 的所有 TextRun（兜底）、`media.js` 的附件名（原始字段）
3. **新增断言 `F1`**：逐 XML 部件扫描非法字符——这类缺陷必须有永久守卫（此前只靠「Word 能转 PDF」隐式发现）
4. 顺带修 `runs.js` 的导入遗漏（只加调用没加 import，导致渲染静默降级为 40 条错误）

**验收**：r035 断言 12/12、`F1` 通过；用 Word COM 实际打开成功（3 页）；修复前的 r032 会被 `F1` 直接抓出。


## r040（2026-10-17）：修复文档大标题丢失（影响所有 /docx/ 链接）

**现象**：用户反馈「没有正确识别到文档大标题」。实测三篇模板文档的产物全部以「未命名文档」为标题。

**根因**：两处叠加——
1. `/docx/<token>` 链接**从未获取标题**：代码里 `title` 直接写死空串（`get_node` 只服务 wiki 链接）
2. `buildDocx` 在标题为空时**把字面量「未命名文档」写进了正文**，成了假大标题

而真实标题就在**根 `page` 块的文本**里（飞书把文档标题挂在根块 text 上，不是独立块）。实测：
竞品功能调研 ｜ 长期项目方案与执行（含里程碑看板）｜ 部门季报/半年报/年报 —— 三篇全部丢失。

**修复**：
1. `api.js` 新增 `extractPageTitle()`：从根 `page` 块（或 blockSequence 首块）取标题，`node.title` 为空时兜底
2. `build.js`：取不到标题时**不再写占位文字**（占位只用于文件名兜底，不能进正文）
3. 验收：r040 文件名 `竞品功能调研.docx`、首段 FdeTitle = 真标题、全文无「未命名文档」

## r046–r047（2026-10-17）：引用块重做（双竖线 + 灰色调）+ 大文档卡死修复

**用户反馈**：引用块出现两条竖线且不对齐；引用样式要改成在线文档那样的灰色调。

**双竖线根因**：引用块的边框原先加在 `Quote` **段落样式**上，而引用里常含列表——
列表段落带 `numPr`，**编号自带的缩进（left=720）会覆盖样式缩进（420）**，
于是各段左边框落在不同 x 上，看起来就是两条互不对齐的竖线。

**修复**：引用改为**单格表格**承载（对齐 `callout` 的既有做法）：
- 竖线 = 表格左边框，位置固定，一条贯穿整个引用
- 颜色/粗细/内边距全部取自**在线实测**（`tools/probe-quote.mjs`）：
  `#BBBFC4` 灰、1.5pt、内容左缩进 12px；在线本身**无底色**，故不加底纹
- `Quote` 样式只保留段落间距，不再带边框与缩进
- 副作用：引用计入表格数（主文档 23 → 24），`--expect` 已同步

**顺带修大文档卡死（严重）**：主文档（845 块 / 25 页）在加入预热滚动后导出会**整页卡死**
（CDP 连 `Runtime.enable` 都超时）。隔离实验（`tools/probe-scroll-cost.mjs`）证明
纯滚动完全不卡（往返 1–50ms）→ 是采集代码把渲染进程压垮：内嵌表格拼接按整个文档的
`scrollHeight` 估瓦片，大文档上会分配巨型画布 + 生成超大 base64。
修复三道闸：瓦片上限 16→9、输出像素上限 8M（超出先等比缩小）、采集总预算 4 分钟。
结果：r047 导出成功（845 块 / 图 3 / 表格截图 4 / 画板 3 / 1128KB，零异常降级）。

## v0.2.2（2026-10-17）：修复调试 Chrome 后台任务不自动关闭

**用户反馈**：开启的后台任务用完不会关闭，Chrome 残留一堆进程占内存。

**两个根因**：
1. `serve-chrome.mjs` 是 `for(;;)` 死循环，**没有任何退出条件**
2. **没有信号处理**——后台任务被停时 node 死了，但它 spawn 的 Chrome 成了孤儿进程残留（实测 8–10 个）

**修复（机制化，不依赖人记得清理）**：
- **空闲自毁**：任何 CDP 使用方都会刷新心跳文件 `~/.fde-chrome-heartbeat`；
  `serve-chrome` 每 5 秒检查，超过 `--idle` 分钟（默认 10）无人使用就杀掉 Chrome 树并退出
- **信号清理**：注册 SIGINT/SIGTERM/SIGHUP/SIGBREAK/exit，用 `taskkill /F /T /PID` 杀整棵进程树
- **一键停止**：`npm run chrome:stop`（`tools/stop-chrome.mjs`）——先停持有者再杀 Chrome，避免"杀了 Chrome 又被重启"

**实测**：`--idle=1` 启动后 1 分钟自动收尾、chrome 进程 0 个、心跳文件已清理；
直接停后台任务后 chrome 同样归零。

- 引用表格**不做负缩进**（曾有短暂改动跟随官方 -144，实测后按用户要求改回）：
  竖线贴版心、正文靠单元格左内边距 180 twips 缩进

## v0.4.1（2026-10-17）：修复表格变窄（v0.4.0 的严重回归）

**用户反馈**：导出文档里的表格「非常窄」，右侧大片空白。**我只看了页数和断言，没看渲染图** —— 这是流程错误。

**根因**：v0.4.0 的列宽算法里加了 `Math.min(scaled, content)` 的内容上限，
导致各列宽度之和小于版心，而我没有归一化 → 表格只有版心 55% 宽。

**排查中发现的第二个坑**：列宽估算拿不到单元格文本。
表格单元格块**不在 `blockSequence` 里**（只存在于 `blockMap`），
`ctx.byId.get(cellId)` 恒为 undefined → 所有列退化成 MIN 值。
已改为 `byId` 查不到时回退 `ctx.blockMap`（由 `export.js` 传入）。

**排版策略（三轮实测后的结论）**：

| 方案 | 结果 |
| --- | --- |
| 纯 AutoFit（Word 自动调整） | 「字段名称」「必输」被压成竖排，`VARCHAR(64)` 右括号掉行 |
| 纯内容驱动分配 | 长文本列吃掉空间，短列被挤到极限，页数 +1 |
| **固定布局 + 精确下限（采用）** | 表格正好铺满版心，短列横排，关键 token 不折断 |

最终规则：每列宽度 = max(原比例份额, 四字下限, token 宽度)，
超宽从余量最多的列按比例削，最后归一化到版心宽度（合计恒等于 10106）。

**流程修正**：以后凡是**版式相关改动**，必须转 PDF 渲染出图并肉眼确认，
不能只看断言和页数。页数变化不敏感（表格变窄时页数甚至可能不变）。

## v0.9.0（2026-10-18）：内嵌表格导出为真 Excel 对象 + 全模式横页 + 采集提速

### 修阻断：导出变 zip
`injectOleObjects` 用 JSZip 重打包时没传 MIME，JSZip 默认 `application/zip`，

修法：①`generateAsync` 显式传 docx MIME ②下载前再包一层 `new Blob([blob], {type: DOCX_MIME})`
③`e2e` 加 MIME/后缀断言（此前 shim 直接按 filename 落盘，这类问题查不出来）。

### 新增：内嵌表格 → Word 里的真 Excel 对象

- `src/core/sheet/grid.js`：从剪贴板 HTML 抽网格模型（列宽/底色/字色/字号/加粗/对齐/合并），
  `parseStyleDecl` 改为按 `;` 切分（旧正则 `[^-]color:` 会把 `border-color` 当成字色）
- `src/core/ole/xlsx.js`：手写最小 SheetML（6 个部件、inlineStr 省 sharedStrings、样式池化），
  数字格式：`¥#,##0.00;[Red](¥#,##0.00)` / `0.00%` / `yyyy/m/d` / `yyyy/m/d h:mm`
- `src/core/ole/inject.js`：新增 `package` 关系分支（官方同款，不是 Ole10Native）
- 预览图用已采集的整表截图，按真实宽高比摆放（官方固定 414×220 会拉伸）

## v0.9.1（2026-10-18）：多维表格出真表格 + 大附件放开到 200MB

### 多维表格（原来只有一行链接）
真实接口（抓包确认）：`GET /space/api/v1/bitable/<baseToken>/clientvars?tableID=<tableId>`
—— 注意**路径里只放 baseToken**，写成 `<base>_<table>` 会返回 `code:3 Not Found`（实测踩过）。

`data.base` / `data.table` 是 `base64(gzip(JSON))`，用 `DecompressionStream('gzip')` 解：
`viewMap[view].property.fields` 给列顺序、`fieldMap` 给字段名、`groupList[].recordIDList` 给行序、
`recordMap[rid][fid].value` 给单元格值。

渲染：Word 原生表格（表头灰底 + 跨页重复 + ≥7 列横页 + 最多 5 张表）。
实测 IIoT 文档：降级项从「多维表格以链接形式保留」变为**零降级**，表格数 28 → 29。

### 大附件：20MB → 200MB
- `res.blob()` 替代 `arrayBuffer()`（大文件可落磁盘缓存，内存峰值更低）
- 上限提到 200MB（`Ole10Native.dataSize` 是 u32，真正瓶颈是内存）
- 超过 4MB 的 OLE 容器用 `STORE`（不再对已压缩内容做 DEFLATE）

### §2.6 扩展内直取表格数据：本轮未打通（已验证的负面结论）
目标：不跑外部脚本也能拿到单元格 HTML。实测三条路都不通：
1. 合成 `MouseEvent` / `PointerEvent` 点进表格 + 合成 Ctrl+A/C → **零命中**，飞书 canvas 只认 trusted 输入
2. hook `DataTransfer.setData` / `clipboard.write` / `execCommand('copy')` → 由于上一步没进编辑态，一个都没触发
3. `chrome.debugger` 方案（发 trusted 按键）在 CDP 加载的未打包扩展上 **service worker 不响应消息**，
   未完成端到端验证

结论：暂时保留「外部脚本预提取」（`tools/extract-sheets.mjs`），面板一键导出时若没有数据则回退截图。
代码已回退到 v0.9.0 的稳定状态，不影响现有功能。


## v0.9.2（2026-10-18）：修「选了 Excel 对象却出图片」

### 根因
「Excel 对象」需要单元格数据，而数据只有两种来源：①外部脚本 `extract-sheets.mjs` 预提取
②扩展内实时读取。②之前根本没实现，所以面板一键导出时**静默退回截图**——
用户看到的就是「选了 Excel 对象，导出的还是图片」。

### 实现：扩展内实时读取（chromium.debugger + clipboardRead）
- 后台用 `chrome.debugger` 发 **trusted** 鼠标/按键（点进表格 → Ctrl+A → Ctrl+C）。
  这是唯一可行的输入方式：合成的 MouseEvent / PointerEvent / 合成 copy 事件实测全部零命中。
- 内容脚本用 `navigator.clipboard.read()` 取 HTML（新增 `clipboardRead` 权限）。
  拆开做的原因：CDP 的 `Browser.grantPermissions` 在扩展里调不到，靠扩展权限更稳。
- 权限申请放在**面板里选中「Excel 对象」时**（用户手势），不能放导出时——
  权限弹窗会抢焦点，飞书随即节流渲染，整篇采集会变空（实测）。
- 提取放在**所有扫描结束之后**：它会滚动并进入编辑态，夹在扫描中间会打断采集。

### 失败可见
拿不到数据时不再静默：报告里明确写「内嵌表格未读到单元格数据，已用截图代替」，
面板也会提示权限未授予。

### 已知限制
- `chrome.debugger` 无法附加到**已被 DevTools/CDP 接管**的标签页（同一标签只能有一个调试器），
  所以自动化测试环境验证不了这条链路；正常浏览时不受影响。
- 文档若被设置为「禁止复制」，读取会失败并回退截图。


## v0.9.3（2026-10-18）：修「选 Excel 无提示 / 横页不一致」

### 1. 选「Excel 对象」没有任何提示，仍然出图片
`debugger` 之前是**可选权限**，靠面板里 `chrome.permissions.request` 申请。
但该 API 从 service worker 里调用拿不到用户手势，Chrome 会**静默拒绝** ——
所以既不弹窗、也永远拿不到权限，表格只能退回截图。

修法：把 `debugger` 改为**必装权限**。装扩展时就授予，不再需要任何弹窗。
（代价：`chrome://extensions` 里会显示「可以调试此浏览器」的提示，属预期。）

配套：附加失败时**快速失败**（4s 超时）并停止后续表，不再每张表干等 12s；
提示语也从「重新选择一次」改成三条可排查原因（扩展未重载 / 开着 DevTools / 文档禁复制），
且一份文档只提示一次（原来 4 张表刷 4 遍）。

### 2. 子表横页、主表竖页
两套判定标准不一致：原生表格被强制压到版心（永不横页），截图却按宽高比判横页，
于是同一篇文档里横竖混排。

修法：
- 统一为「宽高比 ≥ 2.2 且开关打开」才横页
- **默认关闭**（`landscapeWide: false`），整篇保持同一方向
- 面板新增「宽表横向页」开关，需要时自己打开
