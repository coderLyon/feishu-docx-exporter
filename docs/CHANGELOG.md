## r034–r035（2026-10-17）：修复「导出的 docx 打不开」（严重）

**现象**：用户反馈项目模板（doc2）导出的 Word **完全无法打开**。
**根因**：该文档正文里有一个 `0x08` 控制字符（退格符），被原样写进 `word/document.xml`。
XML 1.0 禁止 0x20 以下的控制字符，Word 于是判定文件损坏——报的是「无法打开」，不会提示非法字符，
排查时容易误以为是样式或关系文件的问题。

**排查方法**（可复用）：逐个 XML 部件用 XML 解析器验证 + 扫描非法码位，一次定位到 `document.xml` 第 9398 字节。
27 份历史产物扫描后仅这一份中招。

**修复**：
1. 新增 `sanitizeXmlText()`：剔除非法控制字符与保留码位（U+FFFE/U+FFFF），并把**落单代理项**替换为 U+FFFD（合法 emoji 是成对代理项，必须保留）
2. 接入三处：`text.js` 的富文本解析出口（段落/标题/表格/代码块/题注的咽喉）、`runs.js` 的所有 TextRun（兜底）、`media.js` 的附件名（原始字段）
3. **新增断言 `F1`**：逐 XML 部件扫描非法字符——这类缺陷必须有永久守卫（此前只靠「Word 能转 PDF」隐式发现）
4. 顺带修 `runs.js` 的导入遗漏（只加调用没加 import，导致渲染静默降级为 40 条错误）

**验收**：r035 断言 12/12、`F1` 通过；用 Word COM 实际打开成功（3 页）；修复前的 r032 会被 `F1` 直接抓出。


## r040（2026-10-17）：修复文档大标题丢失（影响所有 /docx/ 链接）

**现象**：用户反馈「没有正确识别到文档大标题」。实测三篇模板文档的产物全部以「未命名文档」为标题。

**根因**：两处叠加——
1. `/docx/<token>` 链接**从未获取标题**：代码里 `title` 直接写死空串（`get_node` 只服务 wiki 链接）
2. `buildDocx` 在标题为空时**把字面量「未命名文档」写进了正文**，成了假大标题

而真实标题就在**根 `page` 块的文本**里（飞书把文档标题挂在根块 text 上，不是独立块）。实测：
竞品功能调研 ｜ 长期项目方案与执行（含里程碑看板）｜ 部门季报/半年报/年报 —— 三篇全部丢失。

**修复**：
1. `api.js` 新增 `extractPageTitle()`：从根 `page` 块（或 blockSequence 首块）取标题，`node.title` 为空时兜底
2. `build.js`：取不到标题时**不再写占位文字**（占位只用于文件名兜底，不能进正文）
3. 验收：r040 文件名 `竞品功能调研.docx`、首段 FdeTitle = 真标题、全文无「未命名文档」

## r046–r047（2026-10-17）：引用块重做（双竖线 + 灰色调）+ 大文档卡死修复

**用户反馈**：引用块出现两条竖线且不对齐；引用样式要改成在线文档那样的灰色调。

**双竖线根因**：引用块的边框原先加在 `Quote` **段落样式**上，而引用里常含列表——
列表段落带 `numPr`，**编号自带的缩进（left=720）会覆盖样式缩进（420）**，
于是各段左边框落在不同 x 上，看起来就是两条互不对齐的竖线。

**修复**：引用改为**单格表格**承载（对齐 `callout` 的既有做法）：
- 竖线 = 表格左边框，位置固定，一条贯穿整个引用
- 颜色/粗细/内边距全部取自**在线实测**（`tools/probe-quote.mjs`）：
  `#BBBFC4` 灰、1.5pt、内容左缩进 12px；在线本身**无底色**，故不加底纹
- `Quote` 样式只保留段落间距，不再带边框与缩进
- 副作用：引用计入表格数（主文档 23 → 24），`--expect` 已同步

**顺带修大文档卡死（严重）**：主文档（845 块 / 25 页）在加入预热滚动后导出会**整页卡死**
（CDP 连 `Runtime.enable` 都超时）。隔离实验（`tools/probe-scroll-cost.mjs`）证明
纯滚动完全不卡（往返 1–50ms）→ 是采集代码把渲染进程压垮：内嵌表格拼接按整个文档的
`scrollHeight` 估瓦片，大文档上会分配巨型画布 + 生成超大 base64。
修复三道闸：瓦片上限 16→9、输出像素上限 8M（超出先等比缩小）、采集总预算 4 分钟。
结果：r047 导出成功（845 块 / 图 3 / 表格截图 4 / 画板 3 / 1128KB，零异常降级）。

## v0.2.2（2026-10-17）：修复调试 Chrome 后台任务不自动关闭

**用户反馈**：开启的后台任务用完不会关闭，Chrome 残留一堆进程占内存。

**两个根因**：
1. `serve-chrome.mjs` 是 `for(;;)` 死循环，**没有任何退出条件**
2. **没有信号处理**——后台任务被停时 node 死了，但它 spawn 的 Chrome 成了孤儿进程残留（实测 8–10 个）

**修复（机制化，不依赖人记得清理）**：
- **空闲自毁**：任何 CDP 使用方都会刷新心跳文件 `~/.fde-chrome-heartbeat`；
  `serve-chrome` 每 5 秒检查，超过 `--idle` 分钟（默认 10）无人使用就杀掉 Chrome 树并退出
- **信号清理**：注册 SIGINT/SIGTERM/SIGHUP/SIGBREAK/exit，用 `taskkill /F /T /PID` 杀整棵进程树
- **一键停止**：`npm run chrome:stop`（`tools/stop-chrome.mjs`）——先停持有者再杀 Chrome，避免"杀了 Chrome 又被重启"

**实测**：`--idle=1` 启动后 1 分钟自动收尾、chrome 进程 0 个、心跳文件已清理；
直接停后台任务后 chrome 同样归零。

| 引用内项目符号 | **70.22（Δ+25.2）** | **55.20（与正文同 x）** | 与正文同 x |

**根因**：编号定义的首级缩进是 `left=720 / hanging=360`，符号落在 18pt 处；
引用正文却从头排版，于是「适用场景」在 7.2pt、下面两条 bullet 却在 25.2pt —— 差 18pt，肉眼就是没对齐。

**修复**：
- 引用内列表用段落 `ind`（`left=360/hanging=360`，逐级 +420）覆盖编号缩进，符号与引用正文同 x
- 引用表格**不做负缩进**（曾有短暂改动跟随官方 -144，实测后按用户要求改回）：
  竖线贴版心、正文靠单元格左内边距 180 twips 缩进

**新增工具**：`tools/audit-align.mjs`（左对齐体检，支持 `--census` 全文分布统计）、
`tools/probe-quote-align.mjs`（量在线坐标）。

**踩坑**：改代码后未重启 Chrome 导致连测两轮都是旧内容脚本，白测 —— 已写入 VERIFICATION 复测铁律。


## v0.2.4（2026-10-17）：整体协调度审查

用户要求「看看文档整体的协调度」，于是把 24 页全部渲染出来逐页看，配合数值检测，发现 5 个问题：

**1. 有序列表编号倒退（最严重，语义错误）**
现象：`1. 表头更名 / 2. 新增任务来源列 / a. 子项 / **1. 筛选项更名** / 2. / 3.` —— 从 3 跳回 1。
根因：`renderChildren` 的 `prevWasOrdered` 是每层局部变量，`ordered.current` 却是全局的；
嵌套子列表递归时把全局实例号顶掉，父级后续项并进了子列表实例。
修复：实例号改为**按层级**维护（`ordered.byLevel[level]`）并显式传给 `renderOrdered`。
结果：恢复为 1、2、a、3、4、5。

**2. 标题孤悬页底**
修复前 4 处（p3「2.4 接口流程图」、p10「3.5 请求示例」、p19「7.2 …」、p21「附件B…」）。
修复：所有标题样式加 `keepNext`（与下段同页），代码块标题同样处理。
结果：**孤立标题 0 处**；代价是页数 25 → 27（与官方 26 页接近）。

**3. 表格行/代码块跨页劈开**
加 `cantSplit`：表格行不被劈成两半；代码块（单行表格）整体换页，
不再出现「下一页开头只剩两个花括号」。

**4. 采集全空（找到了「首屏偶发漏采」的真凶）**
现象：连续两轮导出 0 图片 / 0 表格，新加的资源自检如实报 `image 0/3、sheet 0/4、whiteboard 0/3`。
根因：Chrome 窗口被遮挡时 `document.visibilityState = hidden`，渲染被节流，
飞书虚拟化只渲染 6 个块（正常约 90 个）。
修复：`serve-chrome` 加三个禁用后台节流的开关，采集前 `window.focus()`。
结果：`visible` 状态、渲染块数 6 → 45，资源恢复 3/4/3。

**5. 剩余可优化项（未做，已记录）**
- 表格列宽按内容均分，导致日期列折行（「2026/09/21」被拆成两行）
- 超宽界面截图缩到版心后偏小，细节吃力（可考虑横向页）
- 大块内容（画板/长表格）不可分割，会留出半页空白


## v0.2.5（2026-10-17）：恢复黑色框线 + 表格列宽内容感知

**用户反馈**：表格的黑色框线被我改丢了。

确认：v0.2.2 跟随飞书官方导出把框线从 `000000` 改成 `DEE0E3`（浅灰），
但用户此前就明确要求「黑色 0.5pt」，跟随官方是错误的判断，已改回 `000000` / sz=4。
表头底纹保留官方值 `EFF0F1`。

**表格列宽改为内容感知**（解决折行）：
旧算法「按原比例缩放 + 统一下限 720twips」会把日期、编码这类不可断 token 压到折行
（`2026/09/21` 被拆成两行）。新算法：
1. 每列先取一个下限 = 该列最长**不可断 token** 的宽度（ASCII 串按字宽累加，中文按 2 字，含单元格内边距）
2. 剩余空间按原始列宽比例分配
3. 下限之和超出版心时才等比压缩（此时只能接受折行）

效果（r064 实测）：
- 「更新日期」列可完整显示 `2026/09/21`、`2026/10/12`，不再拆行
- 「返回码」列可容纳 `401/400/500`，仅「HTTP 504 等」因带"等"字仍折一行
- 黑框线、表头浅灰底、左对齐（与在线 `text-align:start` 一致）


## v0.3.0（2026-10-17）：内嵌电子表格变成**可编辑的 Word 表格**（历史遗留攻坚）

**突破口**：不解析飞书那套稀疏 protobuf（37 个字符串池 + 索引数组 + 合并单元格语义，
猜错会错位），改走**飞书自己的「复制」功能**——表格在 canvas 上渲染，
但它的复制结果是权威 TSV（含空单元格、与网格一一对应）。

**实现链路**：
1. `tools/extract-sheets.mjs`：慢速滚动逐块处理 → 点进表格 → Ctrl+A → Ctrl+C →
   用 CDP 读剪贴板拿到 TSV → 按块 `data-block-id` 写入 `localStorage['fde-sheet-<id>']`
   （处理完按 Esc 退出编辑态，否则后续导出会因页面负载过高而超时）
2. `capture.js`：采集 sheet 时顺带读该键（多键兜底：祖先 id / 容器 id / 下标）
3. `media.js`：有数据就 `buildSheetTable()` 生成 Word 原生表格（黑色 0.5pt 框线、
   表头浅灰底、首行单格视为跨列标题合并），否则回退截图

**实测（主文档，845 块）**：

| 指标 | 改前 r064 | 改后 r068 |
| --- | --- | --- |
| 表格数 | 24 | **28**（4 张内嵌表全部转正） |
| 图片数 | 10 | **6** |
| 体积 | 1128 KB | **672 KB** |
| 跨列合并 | 0 | 8 |
| 断言 | 16/16 | 16/16 |

**宽表保护**：竖版版心装不下时（如 Checklist 的 11 列表）自动回退截图，
并提示「内嵌表格列数较多（N 列），已保留截图以保证版式」——
因为强塞进 A4 会把每列压到 60px，比截图更难看。

**局限**：提取依赖 CDP 的 trusted 按键（扩展内无法发送），
所以目前只用于自动化导出链路（`extract-sheets.mjs` → `export-run.mjs`）。
扩展内的一键导出仍走截图；若要覆盖，需要 `chrome.debugger`（会显示调试横幅）或
反向解析 protobuf（已摸清结构但语义未定，风险高）。


## v0.4.0（2026-10-17）：内嵌表格改为可选 + 全表格减折行 + 工程整理（重要版本）

**1. 内嵌表格导出方式可选（默认图片）**
面板新增「内嵌表格」下拉：
- `导出为图片（推荐）`——默认，版式最忠实，零风险
- `导出为可编辑表格`——生成 Word 原生表格（曲线方案：剪贴板取 TSV），列数过多时自动回退图片

上一版把「可编辑表格」做成唯一行为是不对的：它是兜底能力，不是默认行为。

**2. 全文档表格减少折行**
列宽算法重写为三段式：
1. 以**飞书原始列宽**为基准（作者已按内容调过比例）
2. 保证每列 ≥「最长不可断 token」宽度（`2026/09/21`、`PLAN_WO_JDZJ` 这类不再被拆行）
3. 还有余量就按「缺口」补给内容放不下的列

实测：断词消失；图片模式下页数与纯内容驱动版本持平（30 页）。
中途试过「纯内容驱动」和「按缺口分配」两版，都会让页数 +1，已放弃并记在注释里。

**3. 工程整理**
- 删除 9 个一次性探测脚本（sheet 逆向过程产物），tools/ 从 56 → 47
- README 重写「安装（普通用户）/ 使用 / 开发」三段，明确从 Release 下载 zip 的安装路径
- ARCHITECTURE / TOOLS / VERIFICATION 同步更新

**4. 发布**
GitHub Release `v0.4.0` 附带扩展 zip；此后每个版本都按此流程发布并在 README 保留安装说明。
